# 选型说明：为什么是这个方案

写给以后想改技术路线的人。结论先给：**「听长文」这个需求，edge-tts 是当前最优解；只有在内容不能出本机时，才值得上本地模型。**

## 需求本质决定选型

用户要的不是"生成语音"这个能力本身，而是**把两三万字的中文一口气念完，声音别难听，操作别复杂**。

这个需求有三个隐含约束，直接排除了大部分方案：

- **不需要克隆谁的声音**，只要一个听着舒服的通用中文嗓音
- **文本很长**，模型必须能稳定连续输出，不会念到一半崩掉
- **机器很普通**，常见的笔记本是 4GB 显存甚至核显

第三点最致命。CosyVoice2、VoxCPM2、F5-TTS 在 8GB 以上显存上表现很好，但 4GB 显存跑起来要么 OOM，要么慢到实时率的十分之一——念十分钟的文章要算一小时，体验直接崩掉。

edge-tts 走的是云端合成，本地只需要发 HTTP 请求、收音频字节，**显卡完全不用参与**。合成速度约每秒 88 字，两万字四分钟出结果。

## 2026 年 11 月 GitHub 上的主要候选

以下 Star 数为当日实时抓取值，只列与"读长文"相关的。

**可直接用于本场景的**

- `RVC-Boss/GPT-SoVITS`（65.3k，MIT）——少样本克隆，一分钟录音就能练出像样的音色，中文自然度公认最稳。**如果你想让某位老师的声音长期念课程，选它**；但它要训练、要显卡，属于另一类工具。
- `OpenBMB/VoxCPM`（42.7k，Apache-2.0）——无 tokenizer，支持"声音设计"（用文字描述一个嗓音）与克隆。许可证宽松，商用友好。显存需求偏高。
- `debpalash/VoiceStudio`（113.7k，AGPL-3.0）——本地版 ElevenLabs，克隆、配音、转写、有声书一站式，功能最全。**但 AGPL-3.0 有传染性**：一旦部署成对外服务，整个服务端必须开源。内部自用没问题，做对外产品不能碰。
- `KittenML/KittenTTS`（16.9k，Apache-2.0）——极小模型，纯 CPU 可跑。音质中规中矩，胜在随便什么机器都能跑。
- `QwenAudio/CosyVoice`（24.4k，Apache-2.0）、`QwenLM/Qwen3-TTS`（14.5k，Apache-2.0）——阿里系，中文与多语种都强，Qwen3-TTS 支持流式。

**不建议采用的**

- `coqui-ai/TTS`（46.3k，MPL-2.0）——2024 年 8 月后停止更新，公司已关停。经典但已死。
- `2noise/ChatTTS`（40k，AGPL-3.0）——当年很火，专攻口语对话感，但更新放缓，且 AGPL。
- `index-tts/index-tts`（25.2k）——效果很好，但仓库挂的是 GitHub 无法识别的自定义许可，商用前必须逐字读 LICENSE。
- `babysor/MockingBird`——年代久远，维护停滞。

## 三个容易忽略的合规点

第一，**代码许可证不等于模型权重许可证**。不少项目代码 Apache/MIT，但权重另有一份限制商用或限制月活的协议，两个都要看。

第二，**克隆真人声音必须有书面授权**。中国《民法典》第 1023 条规定，对自然人声音的保护参照适用肖像权的规定。用同事、老师、任何真人的声音训练模型，口头同意不够。

第三，**对外发布的 AI 音频要加标识**。《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日施行，要求生成合成内容添加显式或隐式标识。做课程、短视频、对外售卖内容时这是硬要求。

本工具默认使用官方预置音色、不克隆真人，天然规避第一个问题；第二个仍需在发布环节自行处理。

## 何时应该换掉 edge-tts

- **内容不能出本机**（未公开的财务、病历、合同）→ 换 CosyVoice2 或 VoxCPM2，接受速度损失
- **必须用特定人的声音** → GPT-SoVITS，先训练
- **完全离线环境**（无网络、内网隔离）→ KittenTTS 或 MOSS-TTS-Nano，纯 CPU
- **要流式、要低延迟对话** → Qwen3-TTS 或 CosyVoice，做流式封装

换后端时，只有 `app.py` 里的 `synth_chunk()` 需要重写；切片、时间轴映射、缓存、前端都不用动。前提是新后端能返回**句级或词级时间戳**，否则逐句高亮会退化成按字数估算。
